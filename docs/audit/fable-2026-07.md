## Architecture (as mapped during the audit)

ge is a C++20 reusable rendering/streaming engine (built into a static libge.a and consumed as a git submodule) layered on sokol_gfx + SDL3. The rendering core has three tiers. (1) A platform SokolContext owns the window, GPU device/swapchain, and per-frame drawable acquisition: src/SokolContext.mm (Apple/Metal, compiled with SOKOL_IMPL) and src/SokolContext_android.cpp (Android, runtime Vulkan-or-GLES3 selection via an abstract M base with GlesM/VkM subclasses). (2) A render host (src/render/DirectRenderHost.mm for direct on-device rendering; src/bridge/*WireBridge for the brokered H.264-streaming path, largely dormant/pending 🎯T34) drives per-frame Context refresh, OS-event pumping, resize staging, lifecycle gating, and installs the swapchain-pass factory. (3) The public frame API is ge::Pass (include/ge/Pass.h, src/Pass.cpp), a move-only RAII pass whose destructor runs a teardown closure; the consumer opens exactly one c.swapchainPass() at the top of onRender and the closure does end-pass + commit + present. The run loop lives in src/SessionHost.mm (ge::run → runDirect/runBrokered): pumpEvents → optional on-demand skip → onUpdate → refreshFrame → onMetrics → onRender, all wrapped in an @autoreleasepool per frame (Apple leak control, 🎯T114).

On Android the sokol_gfx implementation is NOT linked into libge; instead a dispatch shim (tools/sokol-dispatch/generated/ge_sokol_dispatch.{h,c}, generated by gen.py) defines real sg_* symbols that forward through a function-pointer table g_ge_sg_api. Two backend .so files (SokolBackendVK_android.c, SokolBackendGLES_android.c) each compile SOKOL_IMPL with hidden visibility and export ge_sokol_bind_{vk,gles}() returning their sg_* table (filled from ge_sokol_fill.inc); SokolContext_android installs the chosen table via ge_sokol_set_api before sg_setup. The Vulkan .so resolves its own Vulkan entry points by dlopen(libvulkan.so) + vkGetInstanceProcAddr (ge_vk_loader.h). Backend choice is a runtime capability probe (ge_vk_probe); Vulkan bring-up failure falls back to GLES3.

Threading/concurrency model: rendering, onUpdate/onRender/onEvent, and all sokol calls run on a single game thread (SDL_main). OS/asynchronous events cross threads only via atomics drained in DirectRenderHost::pumpEvents on the game thread: g_pendingBackPressed, g_pendingMemoryWarning, g_pendingAudioFocusChange (Android JNI UI-thread + iOS notification-queue producers). The app-channel screenshot bridge (detail::captureFrameRGBA) is a worker-thread producer that arms a request (g_ssReq under g_ssMu + g_ssArmed atomic) and blocks on a std::promise until the game thread's endFrame services it; a synchronous variant (captureFrameRGBASync) runs inline for the headless 🎯T124 render-to-PNG path. Video decode callbacks (VideoToolbox) deliver frames on a decoder thread into a mutex-guarded buffer in PlayerWireBridge. sprite.cpp keeps a process-global sokol resource State (pipeline/sampler/stream-buffer pool) with a sg_add_commit_listener that rewinds it each commit — safe only under the single-game-thread assumption.

Data flow for untrusted input: ged-brokered WebSocket → WebSocketClient::recvFrame → PlayerWireBridge (H.264 NAL split + SessionConfig/DeviceInfo structs) → VideoDecoder → frame buffer → SokolContext present. Asset/provenance data flows from files (manifest.json via manifest.cpp; textures via TextureEncoder offline + a runtime .getex loader that is defined only as a format header here) through Resource/FileIO.

## Load-bearing invariants

- g_ge_sg_api (the sokol dispatch table) MUST be non-NULL before ANY sg_* call. It is 0 until ge_sokol_set_api() runs, and every forwarder in ge_sokol_dispatch.c dereferences it unconditionally — a call before/without a bound backend is a NULL deref.
- ge_sokol_dispatch.h (struct fields), ge_sokol_dispatch.c (forwarders), and ge_sokol_fill.inc (table fill) must enumerate the identical sg_* set; any drift (or a hand-edit of the generated files) leaves a NULL slot that is called through blindly.
- Exactly one swapchain Pass per frame, and sg_begin_pass must be balanced by sg_end_pass with all draw calls strictly between them. SokolContext::beginFrame can skip sg_begin_pass (nil drawable / OUT_OF_DATE swapchain) while the host still returns an 'open' Pass, breaking the balance for that frame.
- A header change must recompile every dependent object file, engine objects included (🎯T100). This is currently NOT guaranteed for engine/vendor TUs (their .d files are generated but never -included).
- ge must never create its own MTLCommandBuffer per frame — sokol-metal owns command-buffer creation/commit/present; a stray uncommitted command buffer exhausts the ~64 in-flight limit and wedges the main thread (documented 🎯T89).
- After a background→foreground transition the stale Metal drawable ref must be cleared before the next beginFrame (🎯T108) or the first foreground frame renders black; on Android the swapchain/EGL surface must be torn down on background and recreated on foreground.
- Untrusted WebSocket payload length must be bounded by kMaxMessageSize (512MB) before allocation; recvFrame currently resizes to an unvalidated 64-bit wire length.
- MeshVertex is exactly 20 bytes and GeTexHeader exactly 16 bytes (static_asserts); little-endian is assumed (Protocol.h static_assert) for all wire struct memcpy round-trips.
- Sprite GPU resources (sg_image/sg_view) must be released before sokol shutdown or while sg_isvalid(); after sg_shutdown they must free nothing (guarded), or they poke a dead pool.
- Vulkan per-frame acquire/submit semaphores must not be reused while a prior frame's use is still pending — with only sync.size() semaphore pairs and no per-frame fence, more in-flight frames than semaphores reuses a still-pending semaphore.
- OS-event atomics (back-press, memory-warning, audio-focus, screenshot arm) are the only sanctioned cross-thread channel to game state; callbacks must run only on the game thread via pumpEvents draining, never directly from the producer thread.

## Trust boundaries

- Network (primary): ged-brokered WebSocket frames decoded in src/bridge/WebSocketClient.cpp (recvFrame reads a 64-bit payload length and resizes an unbounded buffer with no kMaxMessageSize enforcement), then parsed in src/bridge/PlayerWireBridge.cpp (H.264 NAL length-prefixed split) and ServerWireBridge.mm; DeviceInfo/SessionConfig/AspectLock/SafeAreaUpdate structs are memcpy'd byte-for-byte from the wire (include/ge/Protocol.h).
- Compressed video payloads: H.264 NAL units from the network fed into VideoToolbox / MediaCodec / ffmpeg decoders (src/bridge/VideoDecoder_*).
- Filesystem assets: manifest.json parsed by an ad-hoc string scanner in src/manifest.cpp; .getex texture files (format in include/ge/GeTexFormat.h; written by src/TextureEncoder.cpp — header/level-size table/level data are attacker-influenceable if a modified asset is loaded at runtime); images via png.cpp/SDL3_image; mesh binaries (include/ge/ModelFormat.h MeshVertex).
- FFI/JNI: Android GeActivity → native atomics (nativeOnBackPressed/nativeOnTrimMemory/nativeOnAudioFocusChange in DirectRenderHost.mm); Vulkan symbols resolved via dlopen("libvulkan.so") + vkGetInstanceProcAddr (SokolBackendVK_android.c, ge_vk_loader.h); Objective-C/Metal and Swift IAP bridges.
- Environment variables: GE_DAEMON_ADDR (daemon address, host:port), SPYDER_APP_CHANNEL (dev RPC host:port), GE_RENDER_ON_DEMAND.
- Device sensors: accelerometer / rotation-vector samples (rotateAccelToScreen, AccelSynth, Attitude_*) — bounded numeric input but drives camera/parallax math.
- GPU driver responses on Android: Vulkan surface capabilities, formats, memory types, physical-device/queue enumeration in SokolContext_android.cpp createSwapchain/chooseDevice/findMemoryType (return-count and empty-vector handling).

## Strategic recommendations

SYSTEMIC ROOT CAUSE — an incompletely-integrated Android backend. Both surviving findings trace to the same seam: the Android sokol backend (SokolContext_android.cpp with VkM/GlesM + the generated dispatch shim) landed in a later PR (T107, #142) than the host wiring that was supposed to consume it (T38, #113), and the connective tissue between them was never finished. The host still carries "wire this up when the Android backend lands" TODOs (DirectRenderHost.mm:786-797), and the backend still assumes the host will manage its lifecycle. This is a classic parallel-agent / phased-landing hazard: two halves of one contract merged independently, each looking self-consistent, with no compile-time or runtime check that binds them. A principal engineer's first instruction: treat "Android backend integration" as one unfinished objective, not two bugs — audit every consumer of the SokolContext lifecycle API (onBackground/onForeground/paused) and every caller path into the dispatch shim for the same "assumed the other side handles it" gap.

TRUST-BOUNDARY / INVARIANT WEAKNESS — the dispatch shim has no enforced precondition. The invariant "g_ge_sg_api MUST be non-NULL before ANY sg_* call" is stated but nowhere enforced: every forwarder in ge_sokol_dispatch.c dereferences the table pointer unconditionally, and g_ge_sg_api is 0 until ge_sokol_set_api() runs. Finding 2 is one instance (teardown after failed init), but the verifier already noted the same NULL-deref is reachable through sg_isvalid/sg_shutdown on any init-failure or render-skip path. This is a single-point-of-failure primitive sitting directly downstream of a trust boundary (backend selection can fail — Vulkan probe reject, GLES context creation failure on headless/misconfigured surfaces). The strategic fix is not per-call-site guarding but hardening the primitive itself: either a bound flag with a fast unconditional check, or making set_api install a non-NULL no-op/abort-with-diagnostic table as the default so a premature call fails loudly and deterministically rather than as an opaque SIGSEGV. This also protects the related invariant (dispatch.h / dispatch.c / fill.inc must enumerate the identical sg_* set) — a generated no-op default table would surface drift as a benign no-op rather than a NULL slot.

LIFECYCLE / RESOURCE-SAFETY as a cross-cutting theme. Finding 1 exposes that the Android surface lifecycle — the most fragile part of any mobile renderer — is effectively unimplemented on the direct render path: onBackground()/onForeground() never fire, so vkDeviceWaitIdle-before-window-teardown never runs (unconditional resource-safety gap, driver-independent) and swapchain recreation depends entirely on opportunistic VK_ERROR_OUT_OF_DATE_KHR self-heal, which does NOT cover VK_ERROR_SURFACE_LOST_KHR (permanent black screen on those drivers). This intersects with several other stated invariants that this audit could not fully exercise (🎯T108 stale-drawable clearing, the "exactly one swapchain Pass per frame" balance when beginFrame skips sg_begin_pass on nil drawable / OUT_OF_DATE). Recommendation: the SokolContext lifecycle contract should be made explicit and testable — a small state machine (created → running → backgrounded → running) with assertions, driven by a single platform-neutral lifecycle event mapping, rather than ad-hoc SDL-event branches that differ silently between iOS (DID_ENTER_FOREGROUND) and Android (FOCUS/HIDDEN/MINIMIZED). The iOS/Android divergence in which SDL events carry lifecycle is itself a latent trap for the next engineer.

HANDOFF GUIDANCE. Before another engineer touches this: (1) fix the shim primitive first — it is the cheapest, highest-leverage change and it de-risks the lifecycle fix. (2) Then complete the Android lifecycle wiring and reflect backgrounded state in DirectRenderHost::paused() so the run loop skips the render bracket while the surface is gone. (3) Add an integration smoke test on an AVD covering background→rotate→foreground and a forced-init-failure teardown — both surviving findings are invisible to compile-time checks and to the iOS/Metal path, which is why they survived to a release-candidate state. (4) Note the stated-but-unenforced build invariant (🎯T100: engine/vendor .d files generated but never -included) — it means a header change to Protocol.h / the dispatch headers may NOT recompile dependent engine objects, which could let exactly this class of contract-drift bug ship silently; verify it before trusting any incremental build during the fix.
